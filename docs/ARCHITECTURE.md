# ARCHITECTURE — astro-voyager v1.0.0

## Идея

Развитие `RuCatGH/blackHole`: полноэкранный raytrace-шейдер с RK4-геодезикой
Шварцшильда + путешественник по станциям вместо одной сцены.

Бесшовной вселенной нет осознанно: `Rs=1.0` против парсек ломает float-precision.
Паттерн — Station: телепорт меняет skybox-параметры и шейдер, внутри станции
свободный полет WASD + мышь.

## Модули

### Core (headless, без GPU / GLM / GLFW)
- `Catalog` — builtin-каталог 6 станций, зеркало `res/catalog.json`.
  Контракт: `docs/CATALOG.md`.
- `Camera` — yaw/pitch + forward/right/up, `clampNearHorizon(Rs*1.05)`.
  Своя `Vec3` чтобы core собирался без GLM в CI.
- `Geodesic` — CPU-эталон формул из `shaders/bh.frag`:
  `geodesicAcceleration`, `rk4Step`, `traceRay`.
  Используется в `--demo-geodesic` и unit-тестах.
- `Binet` — решение уравнения Бине $d^2u/d\varphi^2 + u = 3M u^2$ ($u = 1/r, M = R_s/2$) для фотонных орбит Шварцшильда.
  Служит независимым аналитико-численным эталоном для кросс-валидации 4D-интегратора `Geodesic.cpp` (сравнение $u(\varphi)$ с погрешностью $< 10^{-4}$ и проверка критического захвата $b_{\text{crit}} = \frac{3\sqrt{3}}{2} R_s$ через `--demo-binet`).
- `Kerr` — численная интеграция нулевых геодезических в метрике Керра для произвольного спина $|a| \le M$ через уравнения Картера в плоскости экватора.
  Включает аналитический расчет критического прицельного параметра $b_{\text{crit}}(a)$ и радиуса фотонной сферы $r_{\text{ph}}(a)$ по Бардину (1972/1973), а также валидацию предельного перехода $a \to 0$ к геометрии Шварцшильда через `--demo-kerr`. **Важное архитектурное ограничение**: модуль является чисто физическим CPU-эталоном; рендерер (`bh.frag`) остается чисто шварцшильдовским.
- `Interaction` — логика захвата курсора, блокировки ввода при фокусе ImGui и clamp камеры у горизонта событий.
- `main` — CLI: `--list`, `--info <id>`, `--demo-geodesic`, `--demo-binet`, `--demo-kerr`, `--test-interaction`, `--version`.

### OpenGL Renderer (`ASTROVOYAGER_ENABLE_GL=ON`)
- `Window` — обертка GLFW: создание окна, контекст OpenGL 3.3 Core, VSync.
- `Shader` — загрузка GLSL из файлов, компиляция vertex/fragment, кеширование и установка uniform.
- `Mesh` (`ScreenQuad`, `LineMesh`) — геометрия fullscreen quad (VAO/VBO/EBO) и полилинии созвездий (GL_LINES, GL_POINTS).
- `Cubemap` — 6 граней скайбокса. Процедурный генератор звездного поля и рукавов Галактики с автозагрузкой локального HDR при наличии.
- `SceneManager` — управление сценами и телепортация (`sgra`, `ori`, `qso-3c273`, `uma`, `m31`, `m1`, `sol`, `m87`, `oj287`, `hyperdisk`, `m51`, `m104`, `psr-vela`, `psr-crab`, `sgr-1806`, `psr-b1913`, `mw`, `m13`), выбор шейдеров, пресеты качества и установка физических параметров; релятивистская кинематика наблюдателя (скорость/beta для сдвига света).
- `PostFX` — пост-процессинговый конвейер: scene FBO (float16 HDR-linear + DEPTH24, пересоздание при resize), цепочка bloom из 5 уровней bright-pass + гаусс-блюр, композит через texelFetch (`post_comp.frag`, единственный тонмаппинг ACES + гамма + зерно на весь кадр), фолбэк blit при отсутствии FBO; доплер-тинт при быстром полёте.
- `AppGL` — главный цикл, WASD-перемещение, обзор мышью, интеграция Dear ImGui (HUD со списком станций, комбобоксом пресетов, слайдерами и FPS), захват скриншотов.

## Рендер станций

- `shaders/quad.vert + bh.frag` — Schwarzschild null-geodesic raytracing с численным RK4.
- `shaders/quad.vert + quasar.frag` — core+disk+jets, procedural billboard квазара 3C 273.
- `shaders/lines.vert + lines.frag` — созвездия Orion (`ori`) и Ursa Major (`uma`) через `GL_LINES` и `GL_POINTS`.
- `shaders/quad.vert + galaxy.frag` — галактики (`m31`, `m51`, `m104`, `mw`), процедурные спиральные impostor-спрайты; форма параметризована per-station (`u_GalSeed/Arms/Pitch/Bulge/Dust/ArmGain`); LOD сближения — объёмные звёзды (18→6) + hero-звёзды с долётом по double-click; `mw` хранит позицию Солнца (`sunWorldPos`) для автопрыжка в `sol`.
- `shaders/quad.vert + nebula.frag` — Крабовидная туманность (`m1`), процедурный impostor-спрайт с пульсаром и волокнами.
- `shaders/quad.vert + pulsar.frag` — пульсары (`psr-vela`, `psr-crab`, `sgr-1806`, `psr-b1913`): наклонный дипольный маяк, дуги магнитосферы; вид параметризован per-station (`u_SpinRate/MagTilt/BeamTint/HaloGain/ArcScale`), тик с реальным периодом в аудио.
- `m_starShader` + `StarPoints` — шаровое скопление (`m13`): детерминированная сфера Пламмера, точки со спектром по величине; между звёздами можно летать.
- `shaders/post_down13/post_up9/post_streak/post_comp/post_fxaa.frag` — пост-стек: bloom-пирамида Jimenez (13-tap down с Karis/soft-knee, 9-tap tent up), анаморфный стрик, ACES-композит и FXAA 3.11; `sky.frag` — аберрация звёздного поля при быстром полёте.
- Скриншоты сохраняются в `docs/screens/`.

### Автоперформанс (Auto-Performance Benchmark)

При старте 3D-сцены (`AppGL`) автоматически включается режим калибровки производительности:
- В течение первых **2.0 секунд** накапливается число отрендеренных кадров и вычисляется средний FPS:
  $$\text{FPS}_{\text{avg}} = \frac{\text{Frames}}{\Delta t}$$
- По результатам замера автоматически активируется оптимальный пресет:
  - $\text{FPS}_{\text{avg}} \ge 55.0 \implies$ **Ultra** (мощные дискретные GPU, максимальная детализация световых колец).
  - $30.0 \le \text{FPS}_{\text{avg}} < 55.0 \implies$ **Med** (комфортный фреймрейт на стандартных дискретных видеокартах).
  - $\text{FPS}_{\text{avg}} < 30.0 \implies$ **Low** (интегрированные видеочипы и ноутбуки, сохранение интерактивности).
- **Ручной override**: комбобокс пресетов в Dear ImGui (`src/AppGL.cpp:192`+) остается активным ручным оверрайдом. Выбор пользователем любого пресета (`Low`, `Med`, `Ultra`, `Custom`) либо перемещение любого регулятора параметров немедленно останавливает автокалибровку и фиксирует пользовательские настройки (при регулировке параметров режим переходит в `Custom`).

### Адаптивный шаг и схема RKF45 (Adaptive Step Size & RKF45)

В шейдере `shaders/bh.frag` фактический шаг марша луча вычисляется по физическому закону $r^{3/2}$, промодулированному фактором сдвига времени (lapse) $f = q / r$ (где $q = \max(r - R_s, 10^{-4} R_s)$):
$$h(r) = \text{clamp}(K \cdot q \cdot \sqrt{r}, h_{\text{min}}, h_{\text{max}})$$
где:
- $K = \frac{h_0}{0.5 R_s \sqrt{1.5 R_s}}$ откалиброван так, чтобы на фотонной сфере ($r = 1.5 R_s$, $q = 0.5 R_s$) шаг точно равнялся базовому шагу пресета $h_0 = \text{u\_StepSize}$;
- $h_{\text{min}} = 0.004 \times h_0$ предотвращает сингулярный коллапс шага у горизонта;
- $h_{\text{max}} = 8.0 \times h_0$ ограничивает максимальный шаг вдали от чёрной дыры.

Модуляция фактором $q$ математически необходима: геодезическое ускорение $\ddot{x}$ имеет асимптотику жёсткости $1/q$ вблизи горизонта, и чистый закон $r^{3/2}$ без множителя $q$ приводил бы к численному катапультированию (slingshot) падающих лучей обратно в космос.

#### Адаптивный контроллер RKF45 (Fehlberg 5(4))
Помимо фиксированного регуляризованного закона, в проект внедрена адаптивная шестистадийная схема Рунге–Кутты–Фельберга RKF45 с контролем локальной погрешности усечения:
- **CPU-эталон** (`src/Geodesic.cpp: rkf45Step`, `traceRayRkf45`): 5-й порядок для распространения состояния, 4-й порядок для встроенной оценки ошибки. Ошибка вычисляется строго по пространственным компонентам (координатное время $dt$ исключено из метрики как подчинённая переменная проекта). Регулятор шага использует формулу $h_{\text{next}} = h \cdot \text{clamp}(0.9 \cdot (\text{tol} / \text{err})^{0.2}, 0.2, 5.0)$.
- **GPU-порт** (`shaders/bh.frag: cartRkf45`, гейтируется `u_Rkf45K > 0.5`): переносит схему RKF45 в GLSL с ограничением бюджета отклонений (до 6 попыток на шаг) для исключения зависания конвейера фрагментного шейдера.
- **Legacy CPU-путь**: исторический метод `traceRay` в `src/Geodesic.cpp` сохраняет интерполяцию с переходом $3 R_s \dots 8 R_s$ для непрерывности валидационных тестов.

## Физическая модель Sgr A* и ограничения

- **Метрика Шварцшильда**: статическое сферически-симметричное гравитационное поле ($M > 0$, заряд $Q = 0$, угловой момент $a = 0$).
- **Численное интегрирование**: 4-й порядок Рунге-Кутты (RK4) для нулевых геодезических в натуральных единицах ($c = 1, G = 1, R_s = 1.0$).
- **Критерии останова луча**:
  - Захват горизонтом событий: $r \le R_s \times 1.001 \implies$ абсолютно черный цвет (тень черной дыры).
  - Свободный выход на бесконечность: $r \ge R_{\text{shell}} \implies$ выборка цвета из cubemap звездного неба.
  - Лимит шагов `maxSteps`: фоновое ослабление (dim fallback).
- **Аккреционный диск и гравитационный redshift (`u_DiskOn`)**:
  - По умолчанию `u_DiskOn = 0`: чистая Schwarzschild-линза бит в бит с исходной моделью.
  - При `u_DiskOn = 1` (переключатель `Disk` в ImGui): тонкий аккреционный диск в экваториальной плоскости ($3 R_s \le r \le 9 R_s$) с учетом гравитационного красного смещения $\sqrt{1 - R_s/r}$ и релятивистского доплеровского биминга орбитального движения кеплеровской плазмы.
- **Осознанные решения и ограничения модели**:
  - **Метрика Керра в рендерере**: отсутствует ($a = 0$). Реальный Sgr A* вращается, однако для стабильного вещественного шейдерного рейтрейсинга и соответствия формулам `RuCatGH/blackHole` в рендерере используется геометрия Шварцшильда без эргосферы и эффекта Лензе-Тирринга. Физика метрики Керра со спином $|a| \le M$ реализована в виде отдельного валидационного CPU-модуля `src/Kerr.cpp`.
  - **Ограничение камеры**: радиус камеры ограничен $R \ge 1.05 R_s$, исключая сингулярности координат и попадание наблюдателя под горизонт событий.

## Настоящие созвездия (Hipparcos)

- Созвездия `ori` (Орион) и `uma` (Большая Медведица) загружаются из каталога `res/constellations.json` с C++ зеркалом в `src/Constellation.h` и `src/Constellation.cpp`.
- Звезды заданы реальными экваториальными координатами Hipparcos (прямое восхождение $\alpha$, склонение $\delta$, видимая звездная величина $V_{\text{mag}}$, HIP ID).
- Отрезки связей соответствуют каноническому астрономическому начертанию: 9 сегментов для Ориона (пояс, плечи, ступни) и 7 сегментов для Большого Ковша (ковш и ручка).
- Подписи и астрометрические характеристики звезд выводятся в панели Dear ImGui активной станции.
